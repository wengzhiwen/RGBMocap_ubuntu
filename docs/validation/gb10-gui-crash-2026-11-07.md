# GB10 GUI abort after reconstruction — 2026-11-07

A user reported that the GUI disappeared after reconstruction on the second
GB10. Opening the same 269-frame project reproduced an interpreter abort
(`none_dealloc: deallocating None`, exit 134). The active stack was in viewport
contact-disc drawing. Tracking, FlowHMR, HaMeR, correction and BVH preparation
had already completed and their saved outputs remained available.

## Diagnosis and fix

A small headless QImage/QPainter reproduction isolated the problem from the
model, video decoder, OpenGL viewport and project. With the installed ARM64
PySide6 6.8.3 bindings on CPython 3.10.22, ordinary void-return painting calls
incorrectly consumed references to `None`. A warmed test of 64 rounds of
`setPen`, `setBrush` and `drawPolygon` lost exactly 192 references. Repeated
painting ultimately exhausted the singleton's reference count and aborted
Python. The same test on the existing amd64 6.8.3 installation lost zero.

The ARM64 quartet (PySide6, Essentials, Addons and shiboken6) is now pinned to
6.7.3 in `installer/linux-aarch64.json`. On the target, the same 192-call probe
lost zero references with that quartet. The public shared-profile setup installed
the replacement and validated its package versions and import locations.
This changes GUI dependencies only: the Windows/amd64 pins, `PROFILES`, CUDA
pins, numerical runtime identities, model files and motion processing are
unchanged. The viewport drawing code did not need modification.

`tools/check_qt_runtime.py` now exercises these bindings without a display,
GPU or inference package. Setup runs it after GUI activation, and the CLI doctor
reports its result. It exits 1 on the original failing runtime and 0 on the
replacement. An unavailable GUI is reported separately, preserving CLI-only use.
Thus a successful import alone can no longer pass this painting check.

## Actual verification

- Opening and playing the user's saved project with the candidate quartet
  completed approximately 12 seconds at 29.92 fps, with zero observed
  video/skeleton and mesh/video frame difference and no renderer errors.
- The regular installed `RGBMoCap.sh` then completed 60 seconds of native mesh
  playback with the bone overlay enabled: 1,799 presented video frames,
  29.98 fps, 1,800 mesh frame observations, zero video/skeleton or mesh/video
  frame difference, zero out-of-clip frames and no renderer errors. The
  269-frame clip looped repeatedly (six decoder seeks). The process exited
  normally with code 0, loaded no inference modules and dispatched no mesh
  computation while paused. This run supersedes the earlier unverified GB10
  playback status for this specific single-person native mesh workflow.
- After deployment through the regular launcher and installer, the target CPU
  suite ran 184 tests: 183 passed, one skipped, zero failures. The amd64 suite
  ran 184 tests: 182 passed, two skipped, zero failures.
- The target's GPU doctor reported 25 OK, five warnings, zero failures, including
  the new binding probe and real CUDA matrix multiplication/NMS in all three
  numerical environments.
- A separate read-only audit of the 269-frame motion confirmed finite tensors,
  body/finger preservation and available original/corrected selected exports.
  HaMeR reported 0 valid left-hand and 139 valid right-hand frames; unavailable
  hand frames preserved the original fingers. This audit does not assert
  ground-truth motion quality or complete hand detection.

This follows the [fresh application deployment report](gb10-fresh-deployment-2026-11-07.md).
That report's GUI check was a short static render; its explicit interactive
playback gap allowed this longer-running binding fault to escape acceptance.
The new functional probe is intended to catch the fault before opening projects.
Raw crash logs, project paths, video/model data and screenshots remain private.

## Repair an existing ARM64 installation

With the GUI closed, in the application directory:

```bash
git pull --ff-only
python3 tools/setup_ubuntu.py --profiles shared
./rgbmocap.sh doctor
./RGBMoCap.sh
```

Completed reconstruction does not need to be rerun. Open the saved project after
updating. The setup command does not replace model or project data.
